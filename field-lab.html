01 / Object authorization

Whose export is it?

You’re signed in as account B. Your export is 2002. Account A owns export 2001. Can you retrieve A’s fictional record?

Ready. Request a fictional export.

Try changing the identifier.

Inspect the code & remediation
// Vulnerable: lookup without ownership check
return exports.find(item => item.id === id);

// Fixed: scope the lookup to the signed-in account
return exports.find(item =>
  item.id === id && item.owner === session.accountId
);

The identifier is not the authorization boundary. Derive the account from the authenticated session, enforce ownership on the server, and retest both authorized and unauthorized requests.

02 / Trust boundaries

A role is just a string?

The fictional app trusts a role supplied by the browser. Change it and request the admin report. Then move the authority back to the server.

Ready. Server-side account role: member.

Can a browser claim more privilege?

Inspect the code & remediation
// Vulnerable: caller chooses authority
allow = request.role === "admin";

// Fixed: use the authenticated server-side session
allow = session.role === "admin";

Never grant privilege based on an editable client value. This exercise models a server decision locally; editing this page never grants real access.
