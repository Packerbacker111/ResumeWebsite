01 / Internal AI tool

From hours of gathering to minutes of context.

Querying separate endpoint telemetry sources was a bottleneck in investigations. I connected an enterprise AI assistant to a written playbook for querying those sources and gave it API access to retrieve the data.

ProblemSlow access to endpoint context
ContributionPlaybook + API connections
Observed outcomeHours → minutes

The work

The playbook guides queries across multiple endpoint telemetry sources. An analyst can ask a question, get relevant telemetry, and spend more of the investigation assessing the evidence. The response decision stays with the analyst.

What I observed

I have seen hour-long investigations move to minutes for me and teammates on many occasions. That is a practical observation from use, not a controlled performance benchmark.

Before / Gather separately

Query individual telemetry sources and bring the context together before assessing the evidence.

After / Ask for context

An analyst question → enterprise AI assistant → written query playbook + APIs → telemetry from multiple sources → analyst assessment.

02 / Workflow automation

Give analysts their time back.

I built Tines stories that connect Microsoft Entra data sources for the Risky Users process and route outcomes based on an internal playbook.

ProblemRecurring manual work
ContributionTines stories across Entra data
Estimated outcome15–20 minutes / day

The work

The stories bring relevant identity-risk context together and apply playbook-defined outcomes to repeatable steps. Analysts can focus on the cases that require their judgment.

Why it matters

The existing estimate is about 15–20 minutes of analyst effort saved per day. This is an estimate for routine work, not a timed performance study.

Before / Repeat the routine

Spend analyst time gathering identity-risk context and carrying out recurring workflow steps.

After / Automate the repeatable steps

Entra risk data → Tines stories → playbook-defined routing → analyst review of cases requiring judgment.

03 / Vulnerability validation

From researcher report to actionable finding.

As the primary HackerOne bug bounty contact, I validate submissions, assess risk, and coordinate remediation with internal stakeholders. The work brings together technical evidence, researcher communication, and the context needed to prioritize a response.

ResponsibilityPrimary HackerOne contact
ContributionValidation + risk assessment
CoordinationResearchers + internal teams

My role

Validate what a report demonstrates, assess the security risk, and coordinate remediation. Clear communication helps translate a researcher’s submission into an issue internal stakeholders can understand and act on.

What the example demonstrates

The walkthrough below illustrates how I would approach a report: establish reproducibility, distinguish observed impact from assumptions, and define what a fix needs to address.

Fictional report / Illustrative approach

Can one account read another account’s export?

This invented scenario uses two test accounts and dummy data. It does not describe an employer incident, a real HackerOne submission, or a measured outcome.

  1. 01 / Establish what is reproducible

    A researcher reports that changing an export identifier returns another account’s file. Create an export as test account A, then request it from test account B. Confirm the accounts have no intended sharing relationship.

  2. 02 / Assess the demonstrated impact

    If B receives A’s dummy file, that demonstrates an authorization failure. Record the endpoint, account permissions, and exposed fields. Identifier predictability and exposure across organizations remain separate questions until tested.

  3. 03 / Communicate an actionable finding

    Give the researcher a clear status update. Give the internal owner reproduction steps, expected versus observed behavior, evidence, and the known scope. Explain why the server must check access to the requested export.

  4. 04 / Define the remediation check

    After a proposed fix, repeat the cross-account request: B should receive no file data, while A should retain legitimate access. Check related export routes before treating the issue as resolved.

The judgment that matters

A successful reproduction establishes a specific access failure. Severity and remediation scope depend on the data, permissions, and affected paths—not the vulnerability label alone.
